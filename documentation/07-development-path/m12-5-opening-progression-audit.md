# Milestone 12.5 Opening Progression Implementation Audit

This audit uses the current `vnext-game-overhaul` implementation at `193634880f2b53a1122ce309bd47f0d8bce88c80`, not prototype history. It covers the opening path through the M13 handoff. The user clarified that the Swamps must be **visible and unlocked after the Mountains boss, with run entry waiting for M13 gameplay**. Package 1 changes planning documentation only.

## Current execution path

1. Real registration creates the player state exercised by `backend/tests/Integration/OnboardingCoreLoopTransitionIntegrationTest.php` (lines 24-38, 151-159). `backend/src/Application/Queries/OnboardingQuery.php` derives `required`/`in_progress` from authored Codex knowledge and `complete` from unit ownership. `backend/content/onboarding/mystic-cave.json` authors two Whim conversations and the four-unit starting Warband. `backend/src/Application/Commands/ProvisionStartingWarbandCommand.php` creates the units, dice, loadouts, squad, and active-squad revision in one idempotent transaction. Phaser routes non-complete onboarding to `OnboardingScreen` in `frontend/src/app/game/scenes/runtime-scenes.ts` (lines 139-149, 1484-1490).
2. `backend/content/config/gameplay.json` declares `region.the_farm` the starting region. `backend/src/Application/RegionAvailabilityPolicy.php` always prepends it to `availableRegionIds` (lines 25-46), and `backend/src/Application/Commands/StartRunCommand.php` exempts it from unlock checking (lines 138-146). It appears in fresh registration bootstrap before the Whim; the run command still rejects entry without an active squad (line 76). Provisioning therefore makes Farm **runnable**, but does not grant a durable Farm region unlock. `backend/tests/Integration/OnboardingCoreLoopTransitionIntegrationTest.php` asserts both the premature bootstrap listing and the squad gate (lines 30-38, 64-75).
3. `backend/content/run-generation/the-farm.json` has combat, loot, Scout dialogue, rest, Mudking boss, and exit. The boss uses `event.farm_boss_completed`; `backend/content/rewards/the-farm.json` grants XP, `unlock.capability.shop_access`, and `unlock.region.mountains` in the same boss resolution. `backend/src/Application/RunNodes/BossNodeResolutionHandler.php` emits the first-victory merchant dialogue only when the Shop unlock outcome is `granted` (lines 70-76). `backend/content/encounters/the-farm.json` uses Shop ownership to choose first/return boss dialogue. The merchant is unnamed in `backend/content/dialogue/the-farm.json`; no production Tooth Collector identity or rescue knowledge is authored.
4. Shop access is correctly authoritative once the Shop unlock exists: `backend/src/Application/Queries/ShopCatalogQuery.php` rejects a locked read (lines 33-36), `backend/src/Application/Commands/PurchaseShopOfferCommand.php` rejects a locked purchase (lines 65-68), and `frontend/src/app/game/screens/camp-screen.ts` derives the button state from the bootstrap unlock (lines 97-101, 298-304). Boss reward unlocks are unique and repeat results are `already_owned`, not repeated grants. `backend/tests/Integration/BossNodeResolutionControllerTest.php` and `MountainsRunLifecycleTest.php` explicitly expect both Shop and Mountains unlocks on the first Farm boss (respectively lines 83-103 and 86-107).
5. With Mountains already unlocked, the player can immediately start its run. `backend/content/run-generation/mountains.json` has kobold combat, loot, rest, hazards, boss, and exit; it has no dialogue node. `backend/content/encounters/mountains.json` contains kobold combatants and a Chief Engineer boss, no Archivist or Wrong Machine trail dialogue. `backend/content/rewards/mountains.json` gives XP only on boss victory. `backend/tests/Integration/MountainsRunLifecycleTest.php` proves the direct Farm-to-Mountains handoff (lines 58-113) and explicitly asserts no Swamp unlock after Mountains completion (lines 228-240).
6. `frontend/src/app/game/screens/camp-screen.ts` lists only bootstrap `available_region_ids` and has no Whim interaction. The client projects only playable regions (`backend/src/Content/ClientContentProjector.php`, lines 50-59); the server availability policy also filters non-playable regions. `backend/src/Application/Commands/StartRunCommand.php` rejects unsupported regions before access checks. A non-playable Swamp identity may be authored under existing region validation, but it would remain invisible in today's Camp contract.

## Ownership and architectural consequences

- Permanent unlocks are the durable authority for Farm, Shop, Mountains, and Swamp destination access. The current `starting_region_id` shortcut must not continue to expose Farm before onboarding if the canonical grant is literal. Fresh bootstrap may then have zero unlocked regions; `frontend/src/app/game/runtime/game-store.ts` currently rejects an empty `available_region_ids` list (lines 276-283), so Package 2 must update that narrow contract and its tests while onboarding keeps the player out of Camp. Unit ownership remains the current onboarding completion marker; this audit proposes no extra story/completion table.
- Dialogue/Codex can carry meaningful rescue, search, and Archivist knowledge. `OnboardingDialogueGuard` is deliberately specific to Mystic Cave; ordinary dialogue IDs are otherwise readable/completable by direct API calls, and choices currently check only Codex prerequisites. Package 3 therefore needs a server-side post-Farm eligibility boundary as well as a Camp affordance. Existing objective completion rewards are an accepted possible transaction owner, but objective visibility/eligibility must be checked before choosing that route.
- Farm's first-victory conversation currently depends on an in-memory boss resolution (`frontend/src/app/game/runtime/battle-presentation.ts` persists only account/battle/run/node IDs, not that resolution). `frontend/src/app/game/scenes/runtime-scenes.ts` shows the merchant follow-up when the in-memory resolution has `firstVictoryDialogueId` (lines 1258-1263, 1341-1363). `CurrentRunQuery` exposes boss conversation only while the boss node is available, so it does not recover a post-victory follow-up. Package 2 must prove reload continuity without trusting client-local state.
- Swamp visibility requires a bounded extension to the existing region projection, not M13 gameplay. The content validator already permits a region without `run_generation_id`; `ClientContentProjector` and `RegionAvailabilityPolicy` currently discard it, while `StartRunCommand` rejects it. Package 5 owns this separation and must preserve server-owned entry authority.

## Package queue recommendation

Keep Packages 2-5 separate because they have distinct transaction and presentation owners, but narrow them to the evidenced gaps above. Package 2 combines the Farm unlock correction with Tooth Collector naming/rescue and durable first-victory follow-up. Package 3 owns the Whim return and Mountains unlock; Package 4 owns Mountains trail/Archivist dialogue; Package 5 owns Mountains boss reveal and the visible, non-enterable Swamp handoff. Package 6 should verify the complete fresh and returning path, especially replay and reload across each handoff; Package 7 remains manual UAT. The provisional queues' Shop unlock and no-Order-troops work are verification/retention, not new unlock or enemy implementations.
